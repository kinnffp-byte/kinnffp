# 김쁘피 여름 보상 아카이브 — 사용 설명서

`kimfp.pages.dev` 용 **정적 사이트**입니다. 빌드 과정이 없어서 파일을 그대로 올리면 바로 뜹니다.

---

## 1. 배포 (Cloudflare Pages)

이전에 안 켜졌던 이유는 **Next.js 소스를 그대로 올렸기 때문**입니다. 그 프로젝트는
`index.html`이 없고 서버(Worker)가 매 요청마다 HTML을 만들어내는 구조라, Pages가
정적 서빙하면 열 파일이 없어서 빈 화면이 떴습니다. 이 폴더는 그 문제가 없습니다.

1. GitHub 저장소에 **이 폴더 안의 내용을 그대로** 올립니다 (`index.html`이 최상단에 오도록).
2. Cloudflare Pages → 해당 저장소 연결
3. **Framework preset: `None`**, **Build command: 비움**, **Build output directory: 비움(또는 `/`)**
4. Deploy

재배포는 바뀐 파일만 덮어쓰고 Commit → 1~2분 → **Ctrl+Shift+R** (안 되면 시크릿 창).

```
index.html      메인 (5개 화면 전부 이 한 파일)
admin/          관리자 (index.html + admin.js)
supabase_전체.sql  DB 설치 SQL — 한 번만 실행
app.js          화면 전환·렌더링·다크모드·확대뷰어
style.css       스타일 (팔레트는 :root 한 곳)
supabase.js     DB 연결 — 아래 2번 참고
fx.js           로딩 게이트
og.jpg          카톡·X 링크 미리보기 썸네일
assets/         이미지 (poster/ 안은 의상 포스터용 3:4 크롭)
```

> **DB를 연결하지 않아도 사이트는 정상 동작합니다.** 연결 전에는 `index.html`에 들어있는
> 기본값으로 표시되고, 연결하면 DB 값이 그 위를 덮어씁니다.

## 2. Supabase 연결 (관리자 페이지 쓰려면 필요)

`supabase.js` 맨 위 두 줄만 채웁니다.

```js
const SUPABASE_URL  = 'https://bpzwdbnglicqmhqtdpiu.supabase.co';
const SUPABASE_ANON = 'eyJhbGciOi…(설정 완료)';
```

- Supabase → New project → Settings → API 에서 **Project ID**와 **anon public 키** 복사
- ⚠️ **한 프로젝트 = 한 사람.** 다른 사람 프로젝트를 재사용하면 옛 데이터가 남습니다.
- Supabase → SQL Editor → 새 쿼리 → **`supabase_전체.sql` 전체를 붙여넣고 Run** (한 번에)
- 마지막에 확인 쿼리가 돌아갑니다. 기대값: profile 1 / promises 10 / fixed_rewards 5 /
  roulette 18 / goods_tiers 6 / merch 12 / outfits 10

## 3. 관리자 페이지

`배포주소/admin/` 으로 들어갑니다. **먼저 비밀번호를 정해야 합니다.**

`admin/index.html` 에서 이 줄을 찾아 고치세요.

```js
var ADMIN_PW = "1234";   ← 소스에 보이니 반드시 버리는 비번으로
```

> ⚠️ 비밀번호는 소스에 그대로 보입니다. **버리는 비번**을 쓰세요.
> anon 키로 쓰기 때문에, 키가 노출되면 비번과 무관하게 수정이 가능합니다.

### 탭 구성

| 탭 | 고칠 수 있는 것 |
|---|---|
| 🏠 사이트 | 제목·설명·로고·상태바·사이드바 메모·푸터·전환 연출 |
| 🧭 목차 | 5칸의 기호·영문 라벨·이름 (사이드바·독·모바일 동시 적용) |
| 📄 메인 | 히어로 전체·지표 4칸·송출 표시·목차 카드 3개·하단 블록 제목 |
| 📈 누적공약 | 머리글·진행률(현재/목표)·하단 안내 + **공약 목록 표** |
| 🎲 방셀보상 | 두 패널 제목·배지·열 나누기 + **확정 단가 표**·**룰렛 표** |
| 🎁 굿즈 | 머리글·제외 안내·갤러리 제목 + **굿즈 단계 표**·**갤러리 표** |
| 👗 의상 | 머리글·컬렉션 2종(대표사진·이름·설명) + **포스터 표** |
| 🎨 테마 | 색 13종 · 컬러피커 + hex 입력 · 즉시 미리보기 · 기본값 복원 |

### 표 다루기
- **+ 줄 추가** → 맨 아래에 빈 줄이 생깁니다.
- **▲▼** 로 순서를 바꿉니다. 사이트에는 이 순서대로 나옵니다.
- **×** 로 지웁니다.
- 각 표마다 **저장** 버튼을 따로 눌러야 반영됩니다. (문구는 탭 아래 "이 탭 문구 저장")
- 굿즈 단계의 **사진 주소**는 한 줄에 하나씩 여러 장 넣습니다.
- 의상의 **컬렉션**이 `summer` = 왼쪽 사진, `ppugini` = 오른쪽 사진을 눌렀을 때 나옵니다.

### 진행률
누적공약 탭의 **현재 누적 / 최종 목표** 두 숫자로 자동 계산됩니다.
공약 금액(`10만`)에서 숫자만 뽑아 비교해서, 달성한 칸은 진하게 / 다음 목표는 포인트 색으로 표시됩니다.

## 4. 화면 구성

| 목차 | 내용 |
|---|---|
| 메인 | 히어로 + 목차 카드 3개 + 의상 2종 미리보기 + 확정 방셀 단가 + 굿즈 소개 |
| 누적공약 | 진행률 게이지 + 공약 10개 로드맵 (가로 스크롤) |
| 방셀보상 | 확정 방셀 단가 5종 + 100개 방셀룰렛 18항목 |
| 굿즈 | 단계별 6종 + 제외 안내 + 전체 굿즈 갤러리 12종 |
| 의상 | 컬렉션 2종(사진 클릭) + 포스터 5종 격자 + 확대 뷰어 |

### 조작
- **왼쪽/오른쪽 의상 사진을 누르면** 그 컬렉션의 포스터 5종이 아래에 펼쳐집니다.
- 포스터를 누르면 확대 뷰어 — **← →** 이동, **ESC** 닫기, "원본 열기"로 4K 원본.
- 사이드바 맨 아래 **NIGHT** 버튼 = 다크모드 (선택은 브라우저에 저장됩니다).
- 일반 이미지(굿즈 등)를 누르면 확대됩니다.

## 5. 색 바꾸기

보통은 **관리자 🎨 테마 탭**에서 바꾸면 됩니다 (13색, 저장하면 전 화면 적용).
직접 고치려면 `style.css` 맨 위 `:root` **한 곳만** 손대면 됩니다.

```css
:root {
  --ink: #11131a;        /* 본문 글자 */
  --paper: #f7f7f3;      /* 시트 배경 */
  --night: #131620;      /* 사이드바·전환 커버 */
  --iris: #737de8;       /* 포인트 색 (킥커·번호·배지) */
  --ice: #b8e9ef;
  ...
}
```

> 원래 CSS에는 팔레트가 **여러 겹으로 중복 정의**돼 있어서 `:root`를 고쳐도 안 먹었습니다.
> 지금은 뒤쪽 중복 선언 25개를 정리해서 `:root`가 유일한 출처입니다.

## 6. 링크 미리보기(카톡·X 썸네일)

크롤러는 JS를 안 돌리므로 **DB가 아니라 `index.html` 상단 메타 태그**를 읽습니다.
관리자에서 제목을 바꿔도 미리보기는 안 바뀝니다.

```html
<meta property="og:title" content="김쁘피 여름 보상 아카이브">
<meta property="og:image" content="og.jpg">
```

- 이미지를 바꿀 땐 **파일명도 같이 바꾸세요** (`og.jpg` → `og-v2.jpg`). 같은 이름이면 캐시됩니다.
- 권장 1200×630, 1MB 이하.
- 카카오 캐시 초기화: `https://developers.kakao.com/tool/debugger/sharing`

## 7. 문제 빠른 참조

| 증상 | 원인 / 해결 |
|---|---|
| 배포했는데 빈 화면 | `index.html`이 저장소 최상단에 있는지 / Build command를 비웠는지 확인 |
| 바꿨는데 안 바뀜 | 캐시 → Ctrl+Shift+R, 시크릿 창 |
| 색을 바꿨는데 일부만 | 그 요소가 팔레트 변수를 안 쓰는 경우 — 어느 요소인지 알려주면 변수로 바꿔줌 |
| 이미지가 안 뜸 | `assets/` 폴더도 같이 올렸는지 확인 |
| 다크모드가 이동마다 풀림 | `localStorage('theme')` 저장 — 시크릿 창에서는 유지되지 않음 |
| 관리자에서 저장했는데 반영 X | `supabase.js` 두 줄 + `supabase_전체.sql` 실행 여부 확인 |
| 관리자에 "DB에 연결되지 않았습니다" | `supabase.js` 두 줄이 아직 `{{ }}` 자리표시자입니다 |
| 관리자 로그인이 안 됨 | `admin/index.html` 의 `ADMIN_PW` 를 아직 안 정했습니다 |
| 표에 저장했는데 사이트에 순서가 다름 | ▲▼ 로 정한 순서가 저장됩니다 — 저장 버튼을 눌렀는지 확인 |
| 굿즈 사진이 한 장만 뜸 | 사진 주소를 **줄바꿈**으로 나눠 넣어야 합니다 (쉼표 아님) |

## 7. SOOP 프사 연동

`admin → 🏠 사이트 → 📺 SOOP 연동` 에서 **아이디만** 넣으면 됩니다. (현재 `gurm01`)

주소는 이 규칙으로 자동 조립됩니다:
```
https://profile.img.sooplive.co.kr/LOGO/{앞2글자}/{아이디}/{아이디}.jpg
gurm01 → .../LOGO/gu/gurm01/gurm01.jpg
```

아이디 하나로 따라오는 것들:
- **브라우저 탭 아이콘(파비콘)** — 주소창에 뜨는 작은 이미지
- **화면 전환 커버 이미지** — 목차 누를 때 덮이는 화면 가운데
- **관리자 페이지 탭 아이콘**

**다른 이미지를 쓰고 싶을 때**만 아래 `커버 이미지` 칸을 채우세요. 채우면 그게 우선하고,
비우면 다시 SOOP 프사로 돌아갑니다. 움짤(.gif)도 됩니다.

`방송국 주소` 칸은 푸터의 **SOOP 방송국 ↗** 링크로 갑니다. 비우면 링크가 숨겨집니다.

> ⚠️ 카톡·X 미리보기 썸네일은 여기서 안 바뀝니다. 크롤러는 JS를 안 돌려서
> `og.jpg` 파일을 그대로 읽습니다 (5번 항목 참고).

## 8. 알아두면 좋은 구조

**관리자 화면 색 ≠ 사이트 색.** 관리자 UI는 `--adm-*` 변수를 따로 씁니다.
예전에는 둘이 `--paper` 같은 이름을 공유해서, 🎨테마를 저장하면 **관리자 배경까지
사이트 색으로 튀는 문제**가 있었습니다. 지금은 분리돼 있어서 테마를 아무리 바꿔도
관리자 화면은 그대로입니다. 바뀐 색은 테마 탭 오른쪽 **미리보기 패널**에서 확인하세요.

테마가 실제로 칠하는 곳:
`--paper`(목차 카드 띠) · `--sheet`(본문 시트) · `--hero`(히어로 배경) ·
`--night`(사이드바) · `--iris`(포인트) · `--ink`(글자) 등 13종.

## 9. 주소(URL) 구조

5개 화면이 `index.html` 하나에 들어 있고, **어느 화면인지는 주소 뒤 `#`로 구분**합니다.

```
kimfp.pages.dev/            → 메인
kimfp.pages.dev/#promise    → 누적공약
kimfp.pages.dev/#reward     → 방셀보상
kimfp.pages.dev/#goods      → 굿즈
kimfp.pages.dev/#outfit     → 의상
```

이렇게 되어서 가능한 것들:
- **새로고침해도 그 화면에 그대로 있습니다.** (예전에는 항상 메인으로 튀었습니다)
- 브라우저 **뒤로/앞으로** 버튼이 화면 이동으로 동작합니다.
- **특정 화면 링크를 바로 공유**할 수 있습니다. 예: 의상만 보여주고 싶으면 `…/#outfit`
- SOOP 게시글 iframe에도 `src="…/#outfit"` 처럼 특정 화면을 바로 띄울 수 있습니다.

없는 이름(`#zzz`)을 넣으면 메인으로 갑니다.

> 폴더로 나누는 방식(`/outfit/index.html`)도 가능하지만, 그러면 화면마다 파일이 복사돼서
> 문구 한 줄 고칠 때 5곳을 손봐야 합니다. 지금 구조는 파일 하나 · 관리자 한 벌로 끝납니다.
> `/outfit` 처럼 `#` 없는 주소를 원하면 말씀해 주세요 (`_redirects` 설정을 추가하면 됩니다).

## 10. 아이패드 목업 하단

예전에 좌측 하단에 **12px 크림색 띠**가 보였습니다. 사이드바 높이가
`calc(100svh - 130px)` 즉 **브라우저 창 높이 기준**이었는데, 사이드바는 실제로는
아이패드 목업 내부(스크롤 영역) 안에 있어서 두 값이 애초에 일치할 수 없었습니다.
창 크기를 바꾸면 틈 두께도 계속 달라졌습니다.

지금은 컨테이너 쿼리(`container-type: size` + `height: 100cqh`)로 **스크롤 영역의
실제 높이를 참조**합니다. 창 크기와 무관하게 항상 딱 맞습니다.

사이드바 내용이 화면보다 길어지면(작은 창) 사이드바 자체가 스크롤되며,
스크롤바는 숨겨져 있습니다.

**하단 독(dock)은 제거했습니다.** 원래 코드에 `display:none`으로 꺼둔 채
마크업과 CSS 70여 줄이 남아 있었습니다(주석: *"Kept in the component for a future
restore"*). 사이드바에 이미 목차 5칸이 다 있어 중복이라 지웠습니다.
아이패드 하단 홈 인디케이터(얇은 막대)는 그대로 둡니다.
